# Мотивация

Кеширование позволит повысить скорость получения данных, снизить нагрузку на систему, повысить ее стабильность.

Кешировать нужно Shop API и MES API, так как эти системы нагружены и медленно работают.

# Предлагаемое решение

Для Shop API нужно внедрить:

1. Клиентское кеширование для статичного контента типа изображений ювелирных изделий. Время жизни - 24 часа.
2. Серверное кеширование Cache-Aside для списка ювелирных изделий. Этот паттерн подходит так как список товаров обновляется не часто, запросы только на чтение, паттерн просто внедрить. TTL 24 часа.
3. Серверное кеширование Refresh-ahead для заказов клиентов. Принудительное обновление каждые 10 минут. Паттерн подойдет потому что ожидается много запросов от большого числа пользователей. Cache-Aside не подойдет - будет много промахов кэша. Паттерн Write-Through нацелен на изменение данных, поэтому не подойдет.

Для MES API нужно внедрить серверное кеширование Write-Through для списка заказов. Write-Through потому что необходима высокая согласованность данных, чтобы другие операторы MES системы сразу увидели изменения статуса заказа.

Инвалидация списка заказов клиентов в интернет магазине будет **Временной**, так как это обусловлено выбором паттерна Refresh-ahead и **Инвалидация по ключу**, так как точно известно, статус какого заказа был обновлён в моменты загрузки файлов, расчета стоимости и тп. и нет необходимости обновлять весь кеш.

Инвалидация списка заказов в MES системе **основана на запросах**, так как использован паттерн Write-Through для поддержания высокой согласованности данных. Инвалидация по времени не подойдет, так как нужно оперативное обновление статуса заказа для операторов MES.

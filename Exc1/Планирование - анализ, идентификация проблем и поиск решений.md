# Проблемные места

## Существующие

- Клиенты не получают свои заказы вовремя, задержка доходит до нескольких месяцев
- Потери или задержки заказов от пользователей API
- Начальная страница системы MES долго загружается
- MES система одна, которая последовательно и долго обрабатывает 3D модели
- Потеря контрактов
- Медленные процессы тестирования и релизов

## Потенциальные

- Производственные мощности, с учетом линейного роста заказов, скоро не будут справляться с нагрузкой
- Не заявлено ограничение на максимальный размер 3D модели, из-за чего может быть загружена MES система большими моделями
- Ручной деплой в release и prod окружение выполняется вручную, что может быть чревато ошибками
- Только один фронтенд разработчик знает React и только частично, а значит скорость и качество доработок могут быть низкими

# Инициативы, которые необходимы для устранения нежелательных ситуаций

- Добавить мониторинг сервисов и очередей
- Добавить логирование и трейсинг
- Горизонтальное масштабирование MES API
- Кеширование
- Автоматизация тестирования
- Автоматизация деплоя

# Инициативы в порядке приоритета

1. Мониторинг сервисов и очередей позволит выявить узкие места, какие сервисы или железо не справляется с нагрузкой.
2. Логирование и трейсинг позволит увидеть ошибки, пропажи заказов, более детально понять, что происходит с системой.
3. Увеличить количество MES сервисов для расчетов моделей, как наиболее вероятный медленный сервис.
4. Кэширование данных MES
5. Автоматизация тестирования и деплоя позволят ускорить выпуск новых версий и , хотя написание автотестов потребует времени.
6. Нанять React фронтендера для устранения проблем в дашборде MES

В первую очередь, нужно добавить мониторинг и логирование, это позволит понять, что происходит, взять ситуацию под контроль и скорректировать план.
Во-вторых, увеличить количество MES сервисов, для более распараллеливания расчета моделей. Конечно, если мониторинг покажет, что узкое место здесь.
В-третьих, добавить кэширование заказов в MES, чтобы менеджеры получали доступ к данным быстрее. Тут надо учесть обновление кэша, если статус заказа меняется или его кто-то берет в работу.

В целевой архитектуре должно быть - система мониторинга, логирования, трейсинга, кэширования, несколько экземпляров MES с балансером.

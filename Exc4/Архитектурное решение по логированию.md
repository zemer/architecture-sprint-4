Логируем системы:

- Shop API
- CRM API
- MES API
- Message Queue

Логи с уровнем INFO:

- Изменение статуса заказа: время, клиент, номер заказа, старый статус, новый статус
- Загрузка файла в 3d files storage (в Shop API): время, клиент, номер заказа, путь к файлу, размер файла
- Логин пользователя в магазин: время, клиент
- Логин пользователя в CRM: время, менеджер
- Логин пользователя в MES: время , оператор
- MES API рассчитала стоимость заказа: время, номер заказа, файл, потраченное время расчета

На уровне DEBUG можно логировать:

- Сообщение попало в очередь: время, сообщение, отправитель, получатель
- Количество полигонов в 3D модели для обработки
- Время обработки запросов базами данных, логируется в API

На уровне WARN можно логировать:

- Неправильные данные для входа в магазин
- Неправильные данные для входа в CRM
- Неправильные данные для входа в MES
- Превышение размера файла 3D модели заданного лимита (100Mb)

# Мотивация

1. Логирование покажет последовательность операций, приводящих к проблеме
2. Позволит найти корень проблемы
3. С помощью логирования можно отследить время выполнения функций
4. Сокращение времени поиска неисправности и увеличение производительности команды
5. Внимание к деталям повышает качество системы и конкурентоспособность

Приоритетные системы для логирования:

- MES API. Сейчас у пользователей API есть жалобы на работу системы
- CRM API. Система является источником для MES, возможно CRM работает некорректно, поэтому заказы застревают.

# Предлагаемое решение

Логирование внедряется с помощью стека ELK.

1. Установить Elastisearch, Logstash, Kibana
2. На хосты с сервисами Shop API, CRM API, MES API, RMQ нужно поставить агент Filebeat.
3. Внедрить в сервисы Shop API, CRM API, MES API вывод логов и направить данные в Filebeat.
4. Настроить шаблон и жизненный цикл индексов.

[Диаграмма компонентов логирования](jewerly_c4_model.drawio)

Доступ к логам должны иметь администраторы системы Чувствительные данные, такие как личные данные пользователей, не должны попадать в логи. По запросу разработчики смогут получить логи.

Политика хранения подразумевает 3 стадии

- горячее хранение в течение 30 дней
- холодное хранение в течение 60 дней
- удаление

Алертинг

- Появление логов уровня ERROR.
- Зависание заказа в любом статусе более 7 дней
- Загрузка 100 за минуту
- 10 попыток входа пользователя за минуту
